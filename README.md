# منصة توقيع مذكرات التفاهم — SRU MoU Signing · v1.6

منصة لإعداد مذكرات التفاهم وتوقيعها إلكترونياً، مع سجل توقيعات **مشفّرة دائماً**.
**المعمارية:** واجهة HTML + Google Apps Script (Web App) + Google Sheets (البيانات والسجلات) + Google Drive (ملفات التوقيعات المشفّرة) + GitHub (المصدر وصفحة الدخول).

---

## خطوات التنفيذ

### المرحلة 1 — Google Sheet (5 دقائق)
1. ادخل بحساب **مالك المنصة** (حساب @sr.edu.sa — يُفضّل حساب خدمة للإدارة وليس حساباً شخصياً).
2. أنشئ Google Sheet جديداً باسم: **`SRU MoU Signing — DB`**.
3. **لا تشاركه مع أحد.** المستخدمون يعملون عبر المنصة فقط ولا يحتاجون صلاحية على الملف.

### المرحلة 2 — Apps Script (10 دقائق)
1. من الـ Sheet: **Extensions → Apps Script**. سمِّ المشروع: `SRU MoU Signing`.
2. احذف محتوى `Code.gs` والصق محتوى **`apps-script/Code.gs`**.
3. أضف ملف HTML: **＋ → HTML** باسم **`Index`** (بدون ‎.html) والصق محتوى **`apps-script/Index.html`**.
4. (اختياري) لإظهار `appsscript.json`: ⚙️ **Project Settings → Show "appsscript.json"** والصق محتواه.
5. من قائمة الدوال اختر **`setup`** ← **Run** ← وافق على الصلاحيات.
   (منذ v1.6 يُنفَّذ `setup` تلقائياً عند أول فتح للمنصة إن لم يُشغَّل، لكن تشغيله يدوياً أولاً يضمن ظهور شاشة الصلاحيات لك.)
   سيُنشأ تلقائياً:
   | العنصر | الوصف |
   |---|---|
   | ورقة `Signers` | بيانات أصحاب التوقيع + بيانات التحقق (بدون أي صورة) |
   | ورقة `Documents` | المذكرات (النص + بيانات التوقيع، بدون صور) |
   | ورقة `SigningLog` | سجل تدقيق: كل توقيع/عرض/إزالة/محاولة فاشلة |
   | ورقة `AccessLog` | سجل الدخول: البريد، التاريخ، الوقت |
   | ورقة `Admins` | مسؤولو المنصة (يُضاف حسابك تلقائياً) |
   | مجلد Drive `SRU-MoU-Signatures-Encrypted` | ملفات التوقيع المشفّرة `.enc` |
   | `PEPPER` في Script Properties | سرّ خادم يُضاف لبصمة التحقق |
6. أضف مسؤولين آخرين (إن وُجدوا) في ورقة **`Admins`**: البريد في العمود A.

### المرحلة 3 — النشر كـ Web App (3 دقائق)
1. **Deploy → New deployment → ⚙️ Web app**.
2. الإعدادات:
   | الحقل | القيمة |
   |---|---|
   | Description | `v1.6` |
   | Execute as | **Me** |
   | Who has access | **Anyone within Sulaiman Al Rajhi University** |
3. **Deploy** وانسخ **Web app URL** (ينتهي بـ ‎`/exec`).
4. افتح الرابط بحسابك وتأكد من ظهور بريدك أعلى الصفحة.

> عند تعديل الكود لاحقاً: **Deploy → Manage deployments → ✏️ → Version: New version → Deploy** — يبقى الرابط نفسه.

### المرحلة 4 — GitHub (5 دقائق)
1. أنشئ مستودعاً (مثلاً ضمن `ictsru`) أو استخدم مستودع ITOC، وارفع مجلد **`mou-signing-v1.6`** كما هو.
2. ضع الشعارات الثلاثة في **`assets/`**.
3. رابط الـ Web App مضبوط مباشرة في زر الدخول داخل **`index.html`** (الخاصية `href`). لتغييره ابحث عن `script.google.com` في الملف.
4. **Settings → Pages → Deploy from branch → main / root → Save**.
5. رابط صفحة الدخول: `https://<org>.github.io/<repo>/mou-signing-v1.6/`
6. (اختياري) لإظهار الشعارات داخل المنصة: في `Index.html` على Apps Script عدّل:
   ```js
   const LOGOS = { sru:'https://<org>.github.io/<repo>/mou-signing-v1.6/assets/sru-logo.png', ictd:'…', itoc:'…' };
   ```
7. أضف الرابط إلى بوابة نماذج ITOC.

### المرحلة 5 — التشغيل الأول والاختبار (10 دقائق)
| # | الاختبار | النتيجة المتوقعة |
|---|---|---|
| 1 | الدخول بحساب ‎@sr.edu.sa | تفتح المنصة + سطر جديد في `AccessLog` |
| 2 | الدخول بحساب Gmail شخصي | رفض من Google |
| 3 | إضافة توقيع (مسؤول) برقم سري مثل `Sru2026abc` | سطر في `Signers` **بدون صورة** + ملف `.enc` في Drive |
| 4 | فتح ملف `.enc` في Drive | نص مشفّر غير مقروء |
| 5 | إدراج التوقيع في مذكرة بالرقم الصحيح | يظهر التوقيع، تُقفل المذكرة، سطر `sign/success` في `SigningLog` |
| 6 | 5 محاولات برقم خاطئ | قفل التوقيع 15 دقيقة + أسطر `failed/locked` |
| 7 | إعادة فتح المذكرة المحفوظة | تظهر "موقّع إلكترونياً — مشفّر" ويلزم الرقم السري للعرض |
| 8 | تعديل نص المذكرة يدوياً في الـ Sheet ثم فتحها | تحذير أحمر: المحتوى لا يطابق بصمة التوقيع |

## نموذج الأمان — "مشفّر دائماً"
| أين | ماذا يُخزَّن | هل الصورة مقروءة؟ |
|---|---|---|
| المتصفح | الصورة مؤقتاً في الذاكرة بعد إدخال الرقم السري فقط | نعم — للحظة العرض/الطباعة |
| الشبكة | نص مشفّر + بصمة تحقق مشتقة | لا |
| Google Drive | ملف `.enc` (AES-256-GCM) | لا |
| Google Sheet | ملح، IV، بصمة `SHA-256(tag + pepper)` | لا (لا توجد صورة إطلاقاً) |
| المذكرات | اسم الموقّع، وقت التوقيع، بصمة المستند | لا |

- **الرقم السري لا يُرسَل للخادم أبداً.** يُشتق منه في المتصفح مفتاحان بملحين مختلفين: مفتاح تشفير، وبصمة تحقق لا تصلح لفك التشفير.
- **الخادم لا يسلّم النص المشفّر** إلا بعد مطابقة بصمة التحقق، مع قفل بعد 5 محاولات (لا يمكن تجاوزه من المتصفح).
- سياسة الرقم السري: 8 خانات على الأقل تشمل حروفاً وأرقاماً.
- **أهم نقطة تشغيلية:** حماية حساب المالك (التحقق بخطوتين) وعدم مشاركة الـ Sheet أو مجلد Drive.
