# منصة توقيع مذكرات التفاهم — SRU MoU Signing · v1.7

منصة لإعداد مذكرات التفاهم وتوقيعها إلكترونياً، مع سجل توقيعات **مشفّرة دائماً**.
**المعمارية:** واجهة HTML + Google Apps Script (Web App) + Google Sheets (البيانات والسجلات) + Google Drive (ملفات التوقيعات المشفّرة) + GitHub (المصدر وصفحة الدخول).

## هيكل المستودع
```
mou-signing-v1.7/
├── index.html              ← صفحة الدخول (ITOC) على GitHub Pages
├── assets/                 ← sru-logo.png · ictd-logo.png · itoc-logo.png
├── apps-script/
│   ├── Code.gs             ← الخادم
│   ├── Index.html          ← واجهة المنصة (الشعارات مضمّنة)
│   └── appsscript.json
├── README.md
└── CHANGELOG.md
```

| # | الخطوة |

| 2 | اختر الدالة **`setup`** ← **Run** ← وافق على الصلاحية الجديدة **Send email as you** (لإرسال رموز الدخول والدعوات) |
| 3 | **Deploy → Manage deployments → ✏️ → New version → Deploy** (الرابط الجامعي لا يتغير) |

> إذا لم يظهر خيار **Anyone** فسياسة Google Workspace تمنع المشاركة الخارجية — يفعّلها مسؤول Workspace، أو اختر **Anyone with Google account** (يحتاج الضيف حساب Google).

## إدارة المسؤولين
- **من المنصة (موصى به):** تبويب **المستخدمون** ← "مسؤولو المنصة" ← البريد (@sr.edu.sa) والاسم ← **إضافة مسؤول**.
- **أو من الـ Sheet مباشرة:** ورقة `Admins` ← سطر جديد: `email` | `name` | `addedAt`.
- لا يمكن حذف نفسك، ويبقى مسؤول واحد على الأقل.

## المستخدمون الخارجيون (ضيوف)
1. تبويب **المستخدمون** ← "المستخدمون الخارجيون" ← البريد + الاسم + الجهة ← **إضافة**.
2. اضغط ✉️ **إرسال دعوة** (يصل الضيف بريد فيه رابط الدخول).
3. في المذكرة اكتب بريده في **"بريد ممثل الطرف الثاني"** واحفظ — هذا ما يجعل المذكرة تظهر له.
4. يدخل الضيف برابط الضيوف ← يكتب بريده ← يصله **رمز من 6 أرقام** ← يدخل.
5. يضيف الضيف **توقيعه بنفسه** (تبويب إدارة التوقيعات) برقمه السري — لا يعرفه أحد غيره — ثم يوقّع المذكرة.

| الضيف يستطيع | الضيف لا يستطيع |
|---|---|
| رؤية المذكرات المرتبطة ببريده فقط | إنشاء مذكرة أو تعديل نصها/شعاراتها |
| إضافة توقيعه الشخصي واستخدامه | استخدام أي توقيع آخر |
| إضافة/إزالة توقيعه في المذكرة | دخول تبويب المستخدمين |

إيقاف الضيف (⏸) أو حذفه يُنهي وصوله فوراً حتى لو كانت جلسته مفتوحة.

## شعارات المذكرة
أعلى كل مذكرة خانتان: **يمين** و**يسار**. لكل خانة: بدون / شعار الجامعة / ICTD / ITOC / **رفع شعار** (يُصغَّر تلقائياً). تُحفظ مع المذكرة وتُطبع معها، وتُقفل بعد التوقيع.

## الإعداد من الصفر (لأول مرة)
1. أنشئ Google Sheet بحساب المالك ولا تشاركه.
2. **Extensions → Apps Script**: الصق `Code.gs`، وأضف ملف HTML باسم `Index` والصق `Index.html`.
3. شغّل **`setup`** ووافق على الصلاحيات.
4. **Deploy → New deployment → Web app**: Execute as **Me**، Who has access **Anyone within Sulaiman Al Rajhi University**.
5. ضع الرابط في زر الدخول داخل `index.html` (ابحث عن `script.google.com`) وارفع المجلد إلى GitHub وفعّل Pages.
6. للضيوف: نفّذ الخطوات 4–6 من جدول الترقية.

## نموذج الأمان — "مشفّر دائماً"
| أين | ماذا يُخزَّن | الصورة مقروءة؟ |
|---|---|---|
| المتصفح | الصورة مؤقتاً بعد إدخال الرقم السري | نعم — لحظة العرض/الطباعة |
| الشبكة | نص مشفّر + بصمة تحقق مشتقة | لا |
| Google Drive | ملف `.enc` (AES-256-GCM) | لا |
| Google Sheet | ملح، IV، `SHA-256(tag + pepper)` | لا |

- الرقم السري لا يُرسَل للخادم أبداً؛ والخادم لا يسلّم النص المشفّر إلا بعد التحقق، مع قفل بعد 5 محاولات.
- رموز دخول الضيوف: صالحة 10 دقائق، 5 محاولات، حد 5 رموز/ساعة، جلسة 6 ساعات. الرد على طلب الرمز موحّد حتى لا يُكشف من هو مسجّل.
- كل دخول وكل عملية توقيع/عرض/إزالة/فشل تُسجَّل في `AccessLog` و`SigningLog`.
- **أهم نقطة تشغيلية:** التحقق بخطوتين لحساب المالك، وعدم مشاركة الـ Sheet أو مجلد Drive.

## حدود معروفة
- منع لقطات الشاشة على مستوى النظام مؤجل (تطبيق سطح المكتب). الحماية الحالية ردعية.
- لا يمكن استرجاع رقم سري منسي: يُحذف التوقيع ويُضاف من جديد.
- حجم المذكرة ~48 ألف حرف، والشعار المرفوع ~44 ألف حرف (حد خلية Sheets).
- رسائل رموز الدخول تُرسَل من بريد مالك السكربت (حصة Workspace: 1500 رسالة/يوم).
